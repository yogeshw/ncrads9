Opening Files

NCRADS9 reads FITS, and reads it in several different senses depending on what the file holds.

What it reads

KindExtensionsNotes
FITS image.fits .fit .fts2D images, and cubes and mosaics as below.
Compressed FITS.fits.gz .fits.fzgzip and fpack, transparently.
Event table.fitsA table of photon events, binned into an image — see below.
ArrayanyRaw pixels with no header, when you can supply the dimensions and type yourself.

Open, and Open as

File → Open (Ctrl+O) reads a file the ordinary way. File → Open as has one entry for each other way of reading the same bytes:

  • Slice — one plane of a cube rather than the cube.
  • RGB Image and RGB Cube, and the same for HSV and HLS — three planes or three files composed into one colour image.
  • Multiple Extension Cube / Multiple Extension Frames — every image extension as the planes of one cube, or each extension in a frame of its own.
  • Mosaic WCS, Mosaic IRAF, their Segment variants and Mosaic WFPC2 — several detectors laid out on the sky.
  • URL — read a FITS file over http rather than from disk.

Formats that are not FITS come in through File → Import: Array (headerless pixels, whose shape and type you supply), NRRD, ENVI, the RGB/HSV/HLS Array variants, and GIF, TIFF, JPEG and PNG. File → Export writes the same set back out.

Mosaics are resampled nearest-neighbour, so a mosaic here is a display aid and conserves no flux. For photometry on a mosaic, build it with reproject or SWarp and load the result.

Files with more than one extension

Instrument files often carry SCI, ERR and DQ extensions together. NCRADS9 asks which you want. DS9 applies its own rule and takes the first without asking, which for such a file is a coin toss; if you prefer that, turn off Ask which extension to load in Preferences → General.

File → Prism (Ctrl+B) opens the file as a structure instead of a picture: every extension, its header, and its table columns, so you can see what is in a file before deciding how to load it.

Event tables and binning

An event table has no image in it — it has a row per photon. NCRADS9 bins those rows onto a grid, and the Bin menu controls how:

  • Average or Sum the values falling in a bin.
  • Bin In, Bin Out, Bin Fit, or a factor from Bin 1 to Bin 256.
  • A buffer size from 128×128 to 8192×8192: how big an image the events are binned into.
  • Binning Parameters for the columns to bin on and the filter to apply.

Keeping settings across loads

By default, opening a file resets the view. File → Preserve During Load has two switches, Pan and Region, which keep the current centre and the current regions when the next image arrives — useful when stepping through exposures of the same field.

Getting images from elsewhere

Analysis → Image Servers fetches a cutout of a named position from DSS, 2MASS, SDSS and others. Analysis → Archives opens the archive web pages. Both need a network connection.

From the command line

ncrads9 image.fits
ncrads9 -zscale -cmap heat image.fits
ncrads9 -tile a.fits b.fits c.fits

Options and filenames are applied in the order you write them, so -log before a file scales that file logarithmically.
